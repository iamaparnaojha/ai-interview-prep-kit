# AI Interview Prep Kit

A premium, research-backed interview preparation workspace built for the Trao full-stack assessment. 

The application architecture isolates untrusted external data (job descriptions and scraped company sites) from acting as direct system instructions. Wait times are masked by premium UI animations and simulated progress states, while the Node.js backend handles crawling, orchestration, coverage checks, and deterministic allocations.

## Architecture & Tech Stack

- **Frontend**: Next.js App Router, Tailwind CSS, Lucide React (Premium dark glassmorphism theme)
- **Backend**: Node.js, Express, strict CORS and session cookie handling (`apps/api`)
- **Database**: MongoDB Atlas for persistence (`apps/api/src/persistence.ts`)
- **LLM**: Google Gemini (`gemini-2.5-flash`) with exponential backoff retry strategies.

## Configuration

Copy `.env.example` to `.env` and fill in your own values. 

| Variable | Required | Purpose |
| --- | --- | --- |
| `GEMINI_API_KEY` | For model generation | Google Gemini API key; leave empty to use the deterministic local fallback during development |
| `GEMINI_MODEL` | No | Gemini model name, default `gemini-2.5-flash` |
| `MONGODB_URI` | Deployment | MongoDB Atlas connection string |
| `MONGODB_DB` | No | Database name, default `ai_interview_prep` |
| `SESSION_SECRET` | Production | Reserved for production session signing |
| `FRONTEND_URL` | No | Allowed frontend origin (e.g. Vercel URL) |
| `NEXT_PUBLIC_API_URL` | Frontend deployment | Browser-visible API base URL; use `http://localhost:4000` locally or the Render backend URL in Vercel |
| `COOKIE_SECURE` | Production | Set `true` if `COOKIE_SAMESITE` is `none` |
| `COOKIE_SAMESITE` | Production | Use `none` for Vercel-to-Render cross-site session cookies; keep `lax` locally. |

## The Pipeline & Generation Sequencing

The `generateKit` pipeline enforces a sequence of deliberate steps, ensuring no single prompt generates the entire kit at once:

1. **Extraction (Deterministic)**: The job description is parsed using regex patterns to find requirement lines. Requirements are classified into technical, behavioural, or domain, and prioritized as 'must' or 'nice'.
2. **Retrieval**: The company website is crawled. Relative links matching 'about', 'career', 'blog', or 'hiring' are discovered, subject to `robots.txt` compliance.
3. **Public Discussion Search**: Gemini is queried to find publicly discussed, generalized information about the company's usual interview process and rounds.
4. **Company Brief**: A dedicated Gemini call consolidates retrieved site data into a tailored company summary. 
5. **Multi-Step Question Generation**: Gemini generates questions *per category* (technical, behavioural, system-design, company-fit) in separate rapid calls to prevent token limits and context bleed.
6. **Coverage Loop**: Deterministic code checks if all 'must-have' requirements were covered by the generated questions. If gaps exist, a second pass explicitly prompts the LLM to write questions matching only the uncovered requirements. A third pass falls back to deterministic rendering if the LLM fails again.
7. **Flashcard Generation**: A separate Gemini call maps requirements to specific conceptual Q&A flashcards.
8. **Scheduling**: Deterministic code allocates exactly the requested number of days. High-priority and harder questions are weighted and placed earlier in the timeline.

## Data State & Re-Generation

- **State Management**:
  - `generated`: Assigned to items generated by the pipeline.
  - `edited`: Assigned automatically via UI hooks whenever standard fields are modified.
  - `pinned`: Assigned manually by users via the "Pin" UI button or when creating a brand-new item manually.
- **Preserving Edits**: During a partial regeneration (e.g., clicking "Regenerate Behavioural"), the backend filters out elements marked `edited` or `pinned`. The LLM generates the remaining slots, effectively replacing only what the user hasn't explicitly customized.

## Creative Feature: Confidence-Weighted Weak Spots

Practice mode incorporates a spaced-repetition analogue feature: Confidence Scoring. After revealing a flashcard (managed via an animated Flip card UI), the user votes their confidence 1-5. 
The system maintains a MongoDB cache (`practice`) storing historical confidence metrics.
The **Knowledge Gaps ("Weak Spots")** dashboard visualizes cards with the lowest confidence, offering interview candidates a targeted review plan leading up to their final days of prep.

## Local Setup & Deployment

**Local Setup**:
```bash
npm install
npm run build --workspace @prep/kit-core
npm run dev
```

**Batch Evaluator (Mandatory Endpoint)**:
```bash
npm run evaluate -- --input <cases.json> --output <kits.json>
```
The evaluator uses the exact same generation and validation modules as the API router.

**Testing**:
Deterministic features (schedule arithmetic, coverage checks, scheme validation) are covered by native Vitest suites.
```bash
npm test
```
